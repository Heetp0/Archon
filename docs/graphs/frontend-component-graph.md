## Analysis

### Major Dependency Clusters
1. **Context & State Hub (`AppContext`, `WebSocketContext`, `ProjectsContext`, `websocketStore`)**: The core state management cluster. Most high-level views, sidebars, and functional modes (`ChatMode`, `AgentMode`) deeply rely on this for real-time reactivity and global state.
2. **Layout & Routing (`App.tsx`, `Home.tsx`)**: `Home.tsx` acts as the main shell, orchestrating the `NavRail`, `ContextSidebar`, `RightSidebar`, and various application modes.
3. **Right Sidebar Sub-System (`RightSidebar.tsx`)**: Forms a dense cluster by composing multiple specialized panels (`ChatInspectorPanel`, `FileViewerPanel`, `CouncilPanel`) that handle complex contextual information.
4. **UI Component Library (`@/components/ui`)**: A vast, loosely coupled set of primitive and complex components (shadcn/ui based) that are imported throughout the application but have minimal outward dependencies.

### Circular or Problematic Imports
- While no strict structural circular imports were found at the module level in this limited scope, there is **heavy coupling** to global contexts across deep leaf nodes (like `RightSidebar` panels directly reading `WebSocketContext`).
- **Mode Coupling:** Some layout components directly import specific feature modes, creating a monolithic structure in `Home.tsx`.

### Recommendations
1. **Decouple Contexts from Leaf Components:** Use prop-drilling for immediate children or specialized custom hooks to reduce direct dependency on `AppContext` and `WebSocketContext` deep within layout components.
2. **Lazy Load Modes:** Use React `lazy` to split the various modes (`ChatMode`, `CouncilMode`, `TutorMode`, etc.) to improve initial bundle size, as `Home.tsx` imports them all directly.
3. **Abstract WebSocket State:** Consider wrapping the `websocketStore` and `WebSocketContext` interactions into domain-specific hooks (e.g., `useChatWebSocket()`) to limit the blast radius when the websocket logic changes.
